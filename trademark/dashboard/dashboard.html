연결 확인 전

이 도구는 심사를 대신하지 않습니다. 점수와 판정은 검토 우선순위용 후보일 뿐이며, 결론은 심사관이 내립니다.

연결 상태

    LLM 교정지시

    모델이 반복해서 놓치는 판단·형식을 단계별로 저장해 두면, 그 단계의 모든 LLM 호출에 자동으로 포함됩니다. (예: "영문 접두 문자 K는 Korea의 약어로 거래사회에서 흔히 사용되어 식별력이 없는 부분으로 검토하라")

    출원건 관리

    출원번호 기준으로 출원건을 만들고, 모든 산출물은 출원건 아래에 버전으로 쌓입니다. 데이터는 이 브라우저의 IndexedDB에만 저장됩니다.

    출원번호메모승인 1승인 2수정일

    모듈 1 — 출원상표 분석

    —

    출원건이 없으면 홈에서 먼저 생성해 주세요. 분석 결과는 심사관이 직접 수정할 수 있고, [승인 1]을 누르면 그 시점의 내용이 버전으로 고정됩니다.

    붙여넣기로 자동 채우기 — IE 심사시스템 화면에서 Ctrl+A → Ctrl+C 한 전체 텍스트를 붙여넣으면 출원번호·표장·지정상품을 추출해 아래 입력칸을 채웁니다

    입력

    1. ① 표장 구성 분석
    2. ② 외국어 의미·칭호 산출
    3. ③ 지정상품 정리·유사군코드 부여

    분석 결과 — 모든 항목은 직접 수정할 수 있습니다

    버전 이력 — 확정 후 수정하면 새 버전이 생기고 이전 버전은 보존됩니다

    아직 확정된 버전이 없습니다.

    모듈 2 — 검색식 작성

    —

    승인 1(출원상표 분석 확정)을 기준으로 ① 검색 용어 추출 → ② 칭호 변형·확장 → ③ 검색식 조립(코드) 순서로 진행합니다. 모든 결과는 직접 수정할 수 있고, [승인 2]를 누르면 그 시점의 검색 준비서가 버전으로 고정되어 검색 에이전트(모듈 3)에서 사용됩니다.

    ① 검색 용어 — core: 반드시 검색할 핵심 용어 / support: 보조 용어

    용어구분우선순위선정 이유

    ② 칭호 변형·확장 — 검색식에 넣을 변형만 체크하세요 (? 는 임의 문자열 와일드카드)

    사용원 용어변형유형변형 이유

    ③ 검색식 — config/query_syntax.json 문법 기준으로 조립·검증 (내부망 반입 시 파일만 교체). 직접 수정 가능

    버전 이력 — 확정 후 수정하면 새 버전이 생기고 이전 버전은 보존됩니다

    아직 확정된 버전이 없습니다.

    모듈 5 — 통지서 작성

    33조 거절이유 문구 생성 (AI) — 판단은 자유롭게, 문장은 템플릿·관용표현 안에서. 결과는 항상 [검토 필요]와 함께 나옵니다
