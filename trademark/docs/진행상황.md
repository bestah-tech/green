## 1. 프로젝트 개요

- **TRADEMARK**: 상표 심사지원 크롬 확장(MV3). K-SUITE(특허심사용 내부 도구)의 구조를 상표심사에 옮긴 것
- 원 지시서: "상표 심사지원 크롬 확장프로그램 개발 지시서" (5모듈·승인 게이트·버전 체인·근거 제한 원칙)
- **빌드 없음** — 폴더 그대로 "압축해제된 확장 프로그램 로드". 외부 CDN·서버 없음. 데이터는 IndexedDB(브라우저 안)에만
- 시작 전 확인사항 답변: 도구 이름 **TRADEMARK** / 내부망 검색시스템 구조 제공 가능 / **LLM 이미지 입력 허용** / HWPX 샘플 제공 예정(아직 못 받음)

### 33조 생성기 파이프라인 (oa33.js / oa33-data.js / oa33-corpus.js)
판단(LLM AnalysisNote JSON) → 규칙 교차검사(§2-2 포팅) → [코퍼스 있으면] 후보 top-10 검색 → LLM 앵커 2~3건 선택
→ 작성(chat, 유형 A~G 템플릿+관용표현+앵커 골격) → 금지어 하드차단(판례·법리, 1회 재실행)
→ 미검증 주장 검출(사용실태·선등록공존 증거 게이트) → 표제 조항 자동 교정 → 6-gram 코퍼스 충실성 리포트
→ [검토 필요] 목록(코드 조립, 필수확인 우선) → 거절이유로 통지서 초안에 삽입.
- 코퍼스(의통서 원문 234건 txt)와 상용구 HTML은 **개인 자산이라 저장소에 없음** — 사용자가 도구에서 파일로 등록 (파서는 실제 파일로 검증 완료: 256레코드, 조항 분포 스펙 실측 일치)
- 34조 계열은 코퍼스 전무 → 생성기는 33조 전용, 34조는 상용구 문구로 커버

## 3. 내부망 환경 (실측 확인된 사실)

- **LLM**: OpenWebUI `https://llm.moip.go.kr`, 모델 gemma4 계열, API 키는 사이트 설정→계정에서 발급. 연결 성공, 모듈 1 실전 분석 동작 확인됨 (401은 키 재붙여넣기로 해결됐음)
- **파일 반입**: 파일전송시스템이 .js를 "확장자 변경/위·변조"로 차단 → **암호 ZIP(tm2026!)만 통과**. 배포 ZIP은 매번 이 암호로 생성해 전달
  - ⚠️ 사용자가 정식 반입 절차(K-SUITE 배포 경로)를 알아보는 중. 확인되면 암호 ZIP 우회는 중단 예정
- **심사시스템(특허넷 계열)**: kpoap.kipo.go.kr:9200 SSO — 크롬에서 열면 옛 브라우저 감지 경고(Netscape 6.0, 인코딩 깨짐). [확인] 후 진행 가능한지 확인 대기 중. IE 전용일 가능성 → 붙여넣기 채우기로 대응
- **미확인**: kpowps.kipo.go.kr(KOMPASS, K-SUITE가 크롬에서 읽는 호스트)가 크롬으로 열리는지 — 열리면 자동 가져오기를 이 화면 기준으로 구현
